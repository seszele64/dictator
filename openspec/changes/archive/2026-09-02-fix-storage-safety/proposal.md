# Proposal: Fix storage and persistence safety (paths, deletes, migrations, config wiring)

## Intent
Audio storage resolves stored paths by blind concatenation, letting absolute paths and `..` traversal escape the recordings directory; history deletion removes the database row before unlinking the file and crashes with `IsADirectoryError` on empty paths, leaving a deleted row behind; legacy databases skip schema migration 2 and fail on `updated_at` forever; recordings queries select a column the table does not have; every command path constructs `DatabaseConfig()` defaults instead of the loaded user configuration; failed or interrupted dictation leaves orphaned recording rows; `keep_wav` leaks WAV files in `/tmp` and never persists them; and `save_audio` moves files into place before claiming them, leaving a deletion window with `audio cleanup`. All eight defects were verified in source and have no regression coverage.

## Scope
**In scope:**
- Path safety in `get_audio_path()` (`whisper_dictate/audio_storage.py:365`): resolve stored paths against the recordings root and reject anything that escapes it (absolute paths, `..` traversal); treat `file_path=""` as an explicit "no file" sentinel instead of resolving to the recordings root; normalize legacy absolute paths (`toggle_dictate.py:166`, `cli.py:472-528` show_history, `cli.py:608-676` delete_history) only when they resolve inside the recordings root, otherwise treat the recording as fileless with a warning and never read or unlink outside the root
- Crash-proof, file-first history deletion (`cli.py:655-667`): unlink the audio file before `delete_recording`; delete row-only for empty/unsafe/missing paths; abort row deletion when unlink fails with a real error so disk and database stay consistent
- Migration backfill (`database.py:268-283`): detect legacy databases (core tables present, no `schema_versions` row) and treat them as baseline schema version 1 so migrations 1→2 run and `update_transcript` (`database.py:806-839`) stops failing with `no such column: updated_at` on old databases
- Schema alignment (`database.py:496`, `:557`, ~`:1010`): remove the phantom `updated_at` from `get_recording`/`list_recordings` selects (the recordings table at `:328-339` has no such column; transcripts at `:352` do, and keep it); switch `_row_to_dict` to strict column mapping so future query/schema drift raises instead of silently dropping columns; `CURRENT_SCHEMA_VERSION` stays 2 — no migration 3
- Config wiring: load configuration before `setup_logging` in the `cli` group callback (`cli.py:64-65` vs `:100-120`); pass the loaded `config.database` through `with_database` (`cli_helpers.py:15`), `DictationService` paths (`dictation.py:63/77/88`), `toggle_dictate.get_db_and_storage()` (~`:92`), and the remaining `DatabaseConfig()` default sites (`cli.py:132-135` dictate disk check, `:386` cleanup_logs, `:484` show_history, `:622` delete_history)
- Failure cleanup (`dictation.py:151-162`, `:260-284`): remove the in-progress recording row on any failure, including `KeyboardInterrupt` (broaden the handler or use a success flag in `finally`); apply the same cleanup to the toggle_dictate failure path
- `keep_wav` persistence (`audio.py:118-120`, `dictation.py:139-141`, `:278-284`): when `keep_wav=True`, persist the WAV into configured storage as the canonical file (row `format='wav'`), keep the MP3 transient for upload only, and unlink both temp files afterwards — no `/tmp` leak
- Atomic save (`save_audio`): stage to a temp file in the destination directory and finalize with `os.replace()`; claim the final `file_path` in the database before finalizing, rolling back on failure, so `audio cleanup --confirm` (`cli.py:752-844`) never deletes a file whose row still references the previous path and no partial file appears at the final path
- Regression tests per domain (path safety, schema integrity, recording lifecycle) at unit and CliRunner integration level; `uv run pytest` and `uv run ruff check .` as gates

**Out of scope:**
- New features (scheduled dictation, notification changes, transcript editing, storage backends other than local filesystem + SQLite)
- Bumping `CURRENT_SCHEMA_VERSION` beyond 2 or adding new database columns/migrations
- Rewriting the `AudioStorage`/`Database` APIs wholesale; only the defect sites are touched
- Migration of recordings already stored outside the recordings root (they become fileless rows with a warning; their files are never deleted)
- Provider, transcription, or notification behavior changes

## Approach
Fix the storage layer first: `get_audio_path()` resolves the stored relative path against the recordings root, normalizes it, and rejects any result outside the root (absolute paths, `..` traversal), while `file_path=""` becomes a "no file" sentinel. `save_audio` stages the audio as a temp file inside the destination directory and finalizes with `os.replace()`, and its callers update the row's `file_path` before finalizing (claim-first) with a rollback on failure — closing the TOCTOU window with `audio cleanup`.

Then the database layer: `_migrate` detects a legacy database (core tables exist but no `schema_versions` row, checked via `sqlite_master`) and treats it as baseline version 1, running every pending migration up to `CURRENT_SCHEMA_VERSION` so legacy databases gain `updated_at` and `update_transcript` works; `get_recording`/`list_recordings` stop selecting the phantom `updated_at`; and `_row_to_dict` uses strict `zip` so drift fails loudly instead of silently dropping columns.

Next the config and lifecycle layer: the CLI group callback loads configuration before `setup_logging` and before any database/storage singleton is initialized, and every consumer (`with_database`, `DictationService`, toggle `get_db_and_storage`, dictation disk check, history/audio/logs commands) uses the loaded `config.database` instead of `DatabaseConfig()` defaults. `delete_history` unlinks files before rows (row-only for empty/unsafe/missing paths, abort row deletion on real unlink errors). The dictation flow removes its in-progress row on any failure including `KeyboardInterrupt`, and `keep_wav=True` persists the WAV into configured storage as the canonical file with the MP3 transient for upload — both temp files unlinked in `finally`.

Finally, regression tests cover every fixed path: path containment and atomic save (`tests/test_audio_storage.py`), delete ordering and empty/unsafe-path handling (`tests/test_history.py`), failure cleanup and `keep_wav` persistence with no `/tmp` leak (`tests/test_dictation.py`), legacy-database backfill and strict row mapping with a hand-built legacy-DB fixture (`tests/test_database_update.py`), and configured-paths wiring via CliRunner (`tests/test_cli.py`). `uv run pytest` and `uv run ruff check .` are the gates.
